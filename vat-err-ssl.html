Почему появляется ERR_SSL_PROTOCOL_ERROR на vat.gov.by?

Портал электронных счетов-фактур (vat.gov.by) использует белорусские криптоалгоритмы СТБ и устаревший компонент ActiveX. Обычный движок Chromium в Google Chrome и Microsoft Edge эти технологии не поддерживает, поэтому при попытке открыть сайт напрямую браузер сбрасывает соединение с ошибкой ERR_SSL_PROTOCOL_ERROR или не видит ключ Авест.

Чтобы портал заработал, его нужно открывать строго в режиме Internet Explorer (IE Mode) внутри Microsoft Edge и с включенными параметрами ActiveX в зоне «Надежные сайты».

Как настроить вручную (и почему это слетает)

  1. Откройте Microsoft Edge → «Настройки» → «Браузер по умолчанию» и разрешите перезагрузку сайтов в режиме Internet Explorer.
  2. Добавьте http://vat.gov.by и https://vat.gov.by в список страниц IE. Минус: вручную Edge удаляет сайт из этого списка ровно через 30 дней.
  3. Откройте «Свойства браузера» Windows (inetcpl.cpl) → вкладка «Безопасность» → «Надежные сайты», добавьте адреса vat.gov.by и включите запуск неподписанных и безопасных элементов ActiveX.
  4. Перезапустите браузер и убедитесь, что USB-токен Авест не заблокирован программой EDeclaration.

Частые вопросы

Можно ли зайти на vat.gov.by через Google Chrome?

Напрямую в современном Google Chrome портал ЭСЧФ не работает, так как Chrome не поддерживает ActiveX и режим IE. В Windows 10 и Windows 11 для vat.gov.by используется встроенный режим Internet Explorer в Microsoft Edge.

Почему через месяц ЭСЧФ снова перестал открываться в Edge?

Встроенный пользовательский список сайтов для режима IE в Edge действует ровно 30 дней, после чего очищается автоматически. Buhly настраивает список через групповую политику Edge без ограничения срока.

Безопасно ли настраивать ЭСЧФ через Buhly?

Да. Buhly весит ~725 КБ (ZIP ~266 КБ), не запрашивает пин-код ЭЦП, не является сторонним браузером и не отправляет ваши данные наружу. Исходный код полностью открыт на GitHub.
